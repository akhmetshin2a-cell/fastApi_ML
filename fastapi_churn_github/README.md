# ML FastAPI: предсказание оттока клиентов

Учебный сервис на Python и FastAPI. По девяти характеристикам клиента он
предсказывает `churn`: `1` — клиент уйдёт, `0` — останется.
Поддерживаются LogisticRegression и RandomForestClassifier.

## Структура

По выбранному учебному формату весь код сервиса находится в `main.py`.
Внутри выделены блоки конфигурации, Pydantic-схем, загрузки данных,
предобработки, обучения, сохранения модели, ошибок и маршрутов API.
Отдельные пакеты `api`, `ml`, `schemas` и `core` не создаются.

```text
fastapi_churn_overall/
├── main.py                   # весь код приложения
├── data/churn_dataset.csv    # исходный учебный датасет
├── models/                   # обученная модель churn_model.joblib включена в проект
├── tests/                    # тесты функций, TestClient и HTTP
├── requirements.txt          # закреплённые версии зависимостей сервиса
├── requirements-dev.txt      # дополнительные зависимости тестирования
├── pytest.ini
├── Dockerfile
├── .dockerignore
├── TESTING.md
└── DOCKER.md
```

## Локальный запуск

Рекомендуется Python 3.13. В терминале перейдите в папку проекта:

```bash
cd /путь/к/fastapi_churn_overall
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8001
```

Если `.venv` уже создана, повторно создавать её не нужно.

- Документация и отправка запросов: http://127.0.0.1:8001/docs
- Состояние сервиса: http://127.0.0.1:8001/health
- Статус модели: http://127.0.0.1:8001/model/status

Команды ниже используют порт 8001. Остановить сервер можно через Ctrl+C.

## Формат датасета

CSV находится в `data/churn_dataset.csv`; путь считается от расположения
`main.py`, а не от текущей папки терминала. Первая строка содержит имена
столбцов; разделитель — запятая; кодировка — UTF-8 (также поддерживается BOM).

| Поле | Тип | Значение |
|---|---|---|
| monthly_fee | float | ежемесячная стоимость тарифа |
| usage_hours | float | часы использования за последний месяц |
| support_requests | int | число обращений в поддержку |
| account_age_months | int | возраст аккаунта в месяцах |
| failed_payments | int | число неудачных платежей |
| region | str | europe, asia, america, africa |
| device_type | str | mobile, desktop, tablet |
| payment_method | str | card, paypal, crypto |
| autopay_enabled | int | автосписание: 0 или 1 |
| churn | int | целевой ответ: 0 или 1 |

В исходном файле 2000 строк. Для CSV обязательны все десять столбцов без
повторений. В признаках допустимы пустые ячейки и маркеры `nan`, `na`,
`null`, `none`; пропуски заполняются внутри pipeline. В `churn` пропуски
недопустимы. Полностью пустой признак в train вызывает понятную ошибку.

Для `/predict` обязательны девять признаков без `churn`, без лишних полей и
без null. Для запроса и CSV действуют одинаковые числовые границы:
модуль стоимости и часов — до 10¹² включительно, модуль целочисленных
счётчиков — до 2⁵³ − 1 включительно. Для `autopay_enabled` допустимы 0 и 1.
Строковые категории могут быть произвольными. Неизвестные
категории обрабатываются OneHotEncoder(handle_unknown="ignore").

## Обучение

```bash
curl -X POST http://127.0.0.1:8001/model/train \
  -H 'Content-Type: application/json' \
  -d '{"model_type":"logreg","hyperparameters":{"C":1.0,"max_iter":1000}}'
```

Для случайного леса:

```bash
curl -X POST http://127.0.0.1:8001/model/train \
  -H 'Content-Type: application/json' \
  -d '{"model_type":"random_forest","hyperparameters":{"n_estimators":100,"max_depth":5,"random_state":42}}'
```

Без тела запроса используется logreg с настройками по умолчанию.
Веса классов можно передать как `"class_weight": {"0": 1, "1": 2}`
внутри `hyperparameters`. Числовые параметры должны быть конечными.
Ответ содержит тип, фактические параметры, дату обучения, размеры выборок
и метрики `accuracy`, `f1` (для класса 1), `roc_auc`.

Данные делятся на 80% train и 20% test с `random_state=42` и `stratify=y`.
Статистики заполнения пропусков, StandardScaler и OneHotEncoder обучаются
только на train. Затем модель оценивается на test. Нельзя оценивать качество
по одним лишь удачным ручным примерам или синтетическим тестам.

Весь pipeline сохраняется вместе с метаданными одним файлом
`models/churn_model.joblib` и автоматически загружается при старте.
Успешное переобучение заменяет активную и сохранённую модель.
Неуспешное обучение или запись файла сохраняют предыдущую модель.

## Предсказание

```bash
curl -X POST http://127.0.0.1:8001/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "monthly_fee":29.9,
    "usage_hours":40.5,
    "support_requests":2,
    "account_age_months":12,
    "failed_payments":0,
    "region":"europe",
    "device_type":"mobile",
    "payment_method":"card",
    "autopay_enabled":1
  }'
```

Пример структуры ответа (числа условные):

```json
{"churn":0,"probabilities":{"0":0.94,"1":0.06}}
```

Можно передать непустой массив таких клиентов: вернётся массив результатов
в исходном порядке. Порядок ключей JSON не влияет на результат.
Вероятности — оценки модели, а не гарантия будущего поведения клиента.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | / | проверка запуска |
| GET | /health | диагностика модели и чтения CSV |
| GET | /dataset/preview?n=5 | первые 1–100 строк |
| GET | /dataset/info | размер, столбцы, распределение churn |
| GET | /dataset/split-info | размеры train/test и распределение классов |
| POST | /model/train | обучение и сохранение модели |
| GET | /model/status | тип, параметры, дата и метрики активной модели |
| GET | /model/schema | входные признаки и их типы |
| GET | /model/metrics?limit=5 | последнее обучение и история |
| POST | /predict | предсказание для клиента или списка |

В `/model/metrics` доступен фильтр `model_type=logreg` или
`model_type=random_forest`, а `limit` принимает значения 1–100.
История хранится в памяти одного процесса; после перезапуска из файла
модели восстанавливается только последнее обучение. Если старый файл не содержит ROC AUC,
статус и история возвращают для него `roc_auc: null`. Сервис рассчитан
на один процесс Uvicorn: память истории и активная модель не разделяются
между несколькими workers.

`/health` читает и проверяет CSV при каждом вызове. HTTP 200 означает, что
приложение отвечает; `status=ok` — доступны модель и непустой датасет,
`status=degraded` — одна из этих частей недоступна. Модель до первого
обучения может отсутствовать. Отсутствие CSV не мешает уже обученной
модели выполнять `/predict`.

## Ошибки и логи

Все HTTP-ошибки возвращаются в формате:

```json
{"code":"MODEL_NOT_READY","message":"Модель не обучена или не загружена. Сначала выполните POST /model/train.","details":null}
```

- 422: неверные поля/типы, пустые данные или неверные настройки обучения.
- 404: CSV или маршрут не найден.
- 503: модель недоступна для предсказания.
- 500: внутренний сбой или ошибка сохранения.

Технические трассировки остаются в журнале. Ключевые события загрузки CSV,
обучения, предсказаний и ошибок выводятся в терминал. В контейнере их
можно читать через `docker logs -f fastapi-churn`.

## Тестирование

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Новые TestClient-тесты используют временные файлы и 40 фиксированных
синтетических клиентов; часть прежних проверок использует исходный CSV.
Пользовательская модель тестами не перезаписывается. Подробнее: [TESTING.md](TESTING.md).

## Docker

Нужен установленный и запущенный Docker Desktop:

```bash
docker build -t fastapi-churn:day14 .
docker run -d --name fastapi-churn -p 127.0.0.1:8002:8000 -v churn-models:/app/models fastapi-churn:day14
```

Откройте http://127.0.0.1:8002/docs и http://127.0.0.1:8002/health.
Первое обучение выполняется внутри контейнера. Том `churn-models` хранит
модель между запусками. Образ не включает локальную `.venv`, тесты и
модель, сохранённую на macOS. Подробнее: [DOCKER.md](DOCKER.md).

Сборка и запуск контейнера в текущей среде пока не проверены: Docker
не установлен. Локальные проверки приложения и тесты выполняются отдельно.
