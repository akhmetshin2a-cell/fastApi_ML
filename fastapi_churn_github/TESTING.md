# Тестирование churn-сервиса

Весь код приложения находится в `main.py`. Тесты находятся в `tests`.

Из папки проекта выполните:

```bash
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Для подробного списка тестов:

```bash
python -m pytest -v
```

Для запуска только новых тестов двенадцатого дня:

```bash
python -m pytest tests/test_day12_units.py tests/test_day12_api.py -v
```

## Что проверяется

- Чтение CSV и преобразование типов.
- Воспроизводимость разбиения train/test и отсутствие пересечения клиентов.
- Заполнение пропусков по статистикам train.
- Обучение обеих моделей и воспроизводимость их предсказаний.
- Полный сценарий через TestClient: CSV → обучение → статус → предсказание.
- Сохранение и восстановление модели при новом запуске lifespan.
- Отсутствующая модель, неверные признаки, отсутствующий, пустой и некорректный CSV.
- Сохранность предыдущей модели после ошибочного переобучения.

## Фикстуры и изоляция

`tests/conftest.py` создаёт 40 фиксированных синтетических клиентов: 20 остались и
20 ушли. Данные намеренно хорошо разделимы: тест проверяет работу pipeline,
а не качество модели на реальных клиентах. Результаты на этих данных нельзя
считать оценкой качества на исходном датасете.

Фикстура `csv_path` записывает синтетические строки в файл с именем
`churn_dataset.csv` внутри временной папки pytest. Фикстура `isolated_service`
подменяет пути CSV и модели и изолирует состояние приложения.
Исходный CSV и пользовательская модель не перезаписываются.

`TestClient` вызывает приложение внутри процесса Python. Для новых интеграционных
тестов не нужно запускать Uvicorn и занимать порт 8000 или 8001. Контекст
`with TestClient(...)` запускает и завершает lifespan приложения.

Ранее созданные unittest-тесты тоже запускаются через pytest. Часть из них
дополнительно проверяет настоящий HTTP-сервер на свободном локальном порту
и использует исходный учебный датасет. Поэтому полный набор требует наличия
`data/churn_dataset.csv`.
